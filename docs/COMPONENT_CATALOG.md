# Учебные компоненты

Реестр для авторов MDX и будущего `author-lesson`. Это документация работающих компонентов; генератор и skill пока не создаются. Сначала проверяйте, подходит ли существующий компонент. Учебная проза остаётся в MDX, изменяемые подписи — в JSON, расчёты — в `src/lib/games/`, состояние — в `src/lib/learning/`.

| Компонент | Вход / назначение | Поведение и ограничения |
| --- | --- | --- |
| `CoreStep.astro` | `id`, `chapter`; слот с прозой | Шаг из метаданных; продолжение открывает следующий, без обязательного ответа. Количество шагов не зашито в код. |
| `PayoffMatrix.tsx` | `model`; необязательный `analysis` | Без `analysis` сохраняет интерфейс главы 1: исходы/выигрыши, выбранная клетка или столбец. С `analysis.mode: explain` включает анализ чистых стратегий. |
| `PayoffMatrix`, practice | `analysis: {mode: 'practice', bestResponsesBeforeCheck?: boolean}`, `task`, `config` | До проверки нет классификации/выводов; по умолчанию нет и лучших ответов. После проверки всех частей открывает анализ. Изменение любого ответа снова его скрывает. Можно исследовать обоих игроков. |
| `NumberGuess.tsx` | `config`, `previousConfig?`, `stage?: 'current' \| 'revised'` | Целое 1–100; сохранение явно кнопкой. Единожды снимает снимок **сохранённого** числа предыдущей главы. Исходное, текущее и повторное числа независимы. Значение слайдера 33 не считается ответом. |
| `StrategyElimination.tsx` | `content: {title, assumption, levels: [{max,target,text}]}`, `locale?` | Назад/дальше/сначала, объявляет диапазон и предпосылки. Показывает утверждённую процедуру, не решает произвольную игру. Нет начисления прогресса. |
| `CommonKnowledgeHats.tsx` | `content: {title,fact,pink,unknown,people,views}` | Перспективы читателя и двух участников; `unknownPerson` скрывает только собственный цвет. Факт и условия публичности остаются явными. |
| `ConceptChain.astro` | `label`, `items: [{label,value}]` | Статическая последовательность. Помечать эвристическую цепочку приблизительной, не выдавать за точный лучший ответ. |
| `Exercise.astro` | `task`; слот условия/ответов/разбора | Обёртка самодостаточного задания. Контроллер управляет только статическим `details[data-task-solution]`, React — собственными элементами. |
| `AnswerPart` | `task`, `partId`, `config` | Native radio или целочисленный ввод. Варианты поддерживают inline code и emphasis, не HTML. Изменение сбрасывает проверку всех частей задания. |
| `CheckTask` | `task`, `config` | Проверяет после валидного заполнения всех частей. Полный разбор доступен и при неверном ответе; можно исправить и перепроверить. |
| `MasteryScore` | `tasks`, `config` | Считает задания, не поля ввода. Семь задач, даже если полей девять. Свободное объяснение не оценивается автоматически. |
| `SelfExplanation.tsx` | `config`, `label` | Сохраняет авторский ответ в `notes.essay` без автопроверки. Возможный разбор — отдельный native details в MDX. Один такой ответ на главу. |
| `ChoiceGroup`, `Mastery`, `WrittenResponse`, `Activity`, `QuickAnswer` | Существующие контракты главы 1 | Совместимость сохранена; `Activity` — набор конкретных демонстраций главы 1, новые лекции не добавляют ветвления в него. |

## Контракт матрицы

`Model`: `id`, `locale`, `caption`, `rows`, `columns`, `payoffs`, `players?: {row,column,meaning}`. Клетка всегда `[выигрыш строки, выигрыш столбца]`. Размерности совпадают; числа конечны, допускаются отрицательные и нули. `outcomes` остаётся для старого режима. Роли и пояснение порядка необходимо задавать явно для новых моделей.

Нажатие имени игрока включает фокус; повторное выключает, другое имя переключает. Для I сравнение идёт по столбцам, для II — по строкам. Контуры групп не меняют геометрию. Все равные максимумы подчёркнуты. Зелёная стратегия превосходит **каждую** альтернативу; розовая уступает хотя бы одной. Строгое отношение — сплошная граница, слабое — пунктир. Полностью одинаковые векторы не означают слабого доминирования. Отдельно рассчитываются лучшие ответы, попарное доминирование и глобальная доминирующая стратегия. Смешанные стратегии не анализируются.

Горизонтальная прокрутка ограничена подписанной фокусируемой областью, если матрица действительно широка; для таблиц лекции 2 значения помещаются при 320px. Состояния имеют текстовые объяснения, кнопки `aria-pressed`, таблица — заголовки строк/столбцов и явное произношение пар. Обе темы используют общие семантические токены.

## Примеры MDX

```mdx
<PayoffMatrix model={models.abstract} analysis={{ mode: 'explain' }} client:load />

<Exercise task={taskById['m03']}>

## Практика 03. Равенство

[Полное условие из утверждённого текста]

<PayoffMatrix model={models['mastery-three']} analysis={{ mode: 'practice' }} task={taskById['m03']} config={config} client:load />
<AnswerPart task={taskById['m03']} partId="m03-part-1" config={config} client:load />
<AnswerPart task={taskById['m03']} partId="m03-part-2" config={config} client:load />
<CheckTask task={taskById['m03']} config={config} client:load />

<details data-task-solution hidden>
<summary>Ответ и объяснение</summary>

[Утверждённый разбор]

</details>

</Exercise>

<NumberGuess config={config} previousConfig={previousConfig} client:load />
<NumberGuess config={config} previousConfig={previousConfig} stage="revised" client:load />
```

Обязательная проверка новой матрицы: обе стороны, все равенства, отсутствие доминирования, отсутствие глобально доминирующей при наличии доминируемой, поведение practice до/после проверки, клавиатура, узкий экран и Graphite.
