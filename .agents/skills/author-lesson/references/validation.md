# Проверки перед редакционным checkpoint

Записывай в `qa.md` проверку, файлы/locator, метод, фактический результат, дефект и остаточный риск. Статусы: pass / fail / not-run / not-applicable с причиной. До появления соответствующего текста или UI тест остаётся not-run, не pass. Не запускай приложение ради инвентаризации источников.

## A — источники и Blueprint

- Зарегистрированы и прочитаны все переданные материалы, включая handout, слайды и исследовательские заметки; известны пропуски и качество OCR. Для нечитаемых существенных формул/матриц нужна визуальная сверка или вопрос редактору.
- Source hashes соответствуют байтам; spans существуют внутри файла/страниц/длительности, excerpt совпадает. Один и тот же пересказ/OCR не считается вторым подтверждением.
- Ключевые определения/числа имеют evidence; спорные выводы не выданы за установленные. Современные дополнения проверены по первичным публикациям с датой, история лекции отделена от современных данных.
- У Blueprint есть главный вопрос, предпосылки, scope, зависимости/понятия, переходы и цели, которые можно проверить; предлагаемые взаимодействия разрешают конкретную трудность. Нет навязанной матрицы или восьми шагов. Пробелы источников и rights/attribution указаны отдельно.

## B — Core RU и математика

- Основной текст читается без раскрытия optional notes, внешнего видео и воспоминаний о выступлении. Определения и необходимые оговорки видны; переход к следующей идее мотивирован.
- Выпиши assumptions, обозначения и домены переменных. Проверь формулы алгебраически, вычисления независимо, конечные случаи — перебором. Сохраняй проверочный код/расчёт и исходные данные рядом с run. Не округляй дискретную границу без анализа самой игры и всех её правил.
- Для матрицы: размерности, конечные значения, обе координаты каждой пары, роли строки/столбца; лучшие ответы включают все равные максимумы; строгое/слабое парное отношение отдельно от глобальной доминирующей стратегии. Идентичные векторы не слабо доминируют друг друга. Анализ чистых стратегий не доказывает утверждение о смешанных.
- Сопоставь независимый расчёт с `compareStrategies` / `analyzePayoffs` из `src/lib/games/dominance.ts`, если применимо. Для нематричной темы используй соответствующий доказательный метод; не притягивай matrix validator к другой модели.
- Контрольные ловушки из примеров: Yale 2×3 — R доминируема C, C не глобально доминирующая; у Ганнибала равенство важно; 45/22 относятся к конкретной авторской задаче Лекции 2, не к произвольной игре с коэффициентом ½. Условные теоретические выводы не выдаются за прогноз каждого человека.

## C — Quick/Mastery RU

- Quick согласован с принятым Core по определениям, результатам, применимости и ограничениям. Не вводит новый необъяснённый тезис; длительность оценена по реальному материалу.
- Для каждой задачи реши условие **без просмотра предполагаемого ключа**, проверь все варианты/границы, затем сравни ключ. Математически правдоподобный distractor не должен тоже быть верным при указанных условиях. Допуски/несколько правильных ответов должны поддерживаться реальным компонентом.
- Каждую задачу прочитай отдельно: здесь есть все необходимые роли, числа, формулы, обозначения, ограничения и локальная матрица/диаграмма, если нужна. Ссылка на Core не заменяет условие. Разбор объясняет рассуждение и ошибку, а не просто букву ответа.
- Objectives покрыты Core и проверкой в Mastery. Есть перенос на новые данные/ситуации, анализ допущений/ошибок и объяснение, когда это соответствует теме. Свободный текст имеет rubric без автоматического балла. Не фиксируй число упражнений по эталонным главам.
- Practice до явного check не раскрывает итог цветом/текстом; после неверного ответа доступен разбор и повторная попытка. Изменение части ответа сбрасывает проверку всего задания. Эта проверка пока по спецификации; поведение в браузере подтверждается после интеграции.

## D — English adaptation и bilingual QA

- Все Quick/Core/Mastery и source-notes, optional explanations, задачи/решения, rubric, metadata, source captions, accessibility labels и понятия есть в обоих языках. Проверяй alignment, а не только количество заголовков.
- Общие stable IDs, objectives, роли/порядок выигрышей, матрицы, числа, обозначения/формулы, assumptions, answer keys, части/options/mappings и source locators совпадают. В тексте отдельно сверяй минусы, кванторы, неравенства и условия выводов: JSON parity не проверяет прозу.
- Проверяй accepted EN термины по первоисточнику и RU–EN glossary. `dominant` ≠ `dominated`, `best response` ≠ `dominance`, `outcome` ≠ `payoff`; mean/median и mutual/common knowledge различаются. Новые термины имеют evidence, допустимые варианты записаны явно.
- EN читается как естественный учебник, сохраняет полноту аргумента без буквального русского синтаксиса. Обратный перевод не считается доказательством точности. Редактор получает обе версии и список содержательных адаптаций.
- Автоматическая сверка не заменяет человеческую двуязычную приёмку. Проблема в принятом RU-тексте становится отдельным editorial change request.

## Структура и проверки приложения

Переиспользуй схемы/функции из `src/lib/content/{schema,translations,editorial-schema}.ts`. Для конкретного нового пакета добавь содержательные проверки: ссылки на существующие IDs/spans, согласованность metadata/MDX, независимые численные fixtures и негативный случай изменённого ключа/пропущенного перевода. Не копируй тест, который всегда сравнивает с тем же значением из JSON.

После разрешённой интеграции:

```sh
npm run check
npm test
npm run build
npm run test:dist
```

Playwright — по текущему `playwright.config.ts`, против production preview под `/knowledge-atlas/`. Если dev занимает 4321, отдельный preview на 4322 и `PLAYWRIGHT_PORT=4322 npm run test:e2e`; сервер сначала должен быть готов. Не меняй зависимости/конфигурацию лишь ради запуска skill.

Для новой главы проверить RU/EN Quick/Core/Mastery, реальные interaction states до/после check, отсутствие JS-ошибок, Continue/reveal-all без обязательной оценки, восстановление после refresh, переход языка с mode/anchor и тем же состоянием, отсутствие перезаписи других глав, источники/таймкоды, клавиатуру/focus/Escape и работу без JS. Не читать настоящие пользовательские заметки: тесты используют отдельный browser context и синтетическое состояние.

Responsive: 320/390/768/1440px, обе темы, отсутствие обрезанных чисел/подписей; широкая таблица прокручивается в подписанной области. Axe WCAG A/AA и ручная проверка клавиатуры. Снимки основных моделей/задач/источников просмотреть до принятия baseline. Вывод build проверить на отсутствие raw sources, run artifacts и личных данных. Существующие тесты двух глав не доказывают полноту третьей автоматически.

## Решение редактора

Применяй рубрику 0/1/2 из `docs/CONTENT_AUTHORING_ADDENDUM.md`; блокирующие фактические/математические ошибки важнее суммы. Убедись, что review manifest охватывает все входы и тексты/ключи. Зафиксируй реальные команды и результаты, ограничения и digest. Ни тест, ни JSON-статус, ни helper не разрешает публикацию.
